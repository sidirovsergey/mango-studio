# Phase 1.8.0a — Stage 03 / Stage 04 behavior shift for asymmetric projects

**Date:** 2026-05-18
**Scope:** projects where `scene.description` ≠ `scene.description_ru` (rare).

## What changed

Phase 1.8.0a routes Stage 03 (`StageScript`) and Stage 04 (`SceneSidePanel`)
text rendering through the new `narrative_paragraph` canonical channel:

```
narrative_paragraph ← scene.narrative_paragraph ?? description_ru
```

Previously these surfaces read `scene.description` directly.

### Symmetric projects (description == description_ru)

**ZERO visible diff.** The render text is bit-identical to pre-1.8.0a.
This is the common case — projects created by the v1.4 generator have
`description == description_ru` because the SceneSchema preprocessor
mirrors both fields bidirectionally on every parse.

### Asymmetric projects (description != description_ru)

**Intentional one-time text shift.** The UI now picks `description_ru`
consistently, regardless of which field carries the "freshest" content.

## Prod impact spot-check

Query on prod 2026-05-18:

```sql
SELECT COUNT(*) FILTER (
  WHERE EXISTS (
    SELECT 1 FROM jsonb_array_elements(script->'scenes') s
    WHERE (s->>'description') IS DISTINCT FROM (s->>'description_ru')
      AND (s->>'description_ru') IS NOT NULL
  )
) AS asymmetric_projects, COUNT(*) AS total_projects FROM projects;
```

Result: **5 of 29** projects (~17%).

Investigation: these are early Phase 1.2/1.3 projects predating the
preprocessor's bidirectional mirror. The divergence is small and the
user-facing Russian text is on `description_ru`. After 1.8.0a, the UI
picks the Russian field — actually more correct for Russian-speaking
users.

## Manual remediation (if user complains)

```sql
UPDATE projects
   SET script = jsonb_set(
       script,
       '{scenes}',
       (SELECT jsonb_agg(
         CASE
           WHEN (s->>'description_ru') IS DISTINCT FROM (s->>'description')
           THEN jsonb_set(s, '{description_ru}', s->'description')
           ELSE s
         END
       ) FROM jsonb_array_elements(script->'scenes') s)
     )
 WHERE id = '<project_uuid>';
```

This copies `description → description_ru`, restoring the pre-1.8.0a
render for that specific project. No regen needed.

## Downstream model prompts — UNCHANGED

The `director-state-summary.ts:82` chain (`description_en ?? description`)
is **explicitly preserved** as the `image_prompt_text` channel.
Veo / Seedance / ffmpeg-api prompt builders read English-preferred text
exactly as before 1.8.0a. The critical regression test is
`director-state-summary.test.ts` case #12 (English context preserved).
Same chain documented inline at:

- `packages/core/src/llm/director-state-summary.ts:87`
- `packages/core/src/media/image-prompts/first-frame.ts:189`
- `packages/core/src/media/video-prompts/_seedance-shared.ts:220`

## Codex audit (2026-05-18) findings — disposition

1. **Empty `image_prompt_text` can silently reach downstream prompt
   builders.** Same risk existed in v1.4 (`description_en ?? description`
   would also return empty if both fields were empty). NOT a 1.8.0a
   regression. Adapter-level rejection deferred to 1.8.0b alongside
   adapter-driven prompt builders.
2. **Production v1.4 schema compatibility not contract-tested.**
   ADDRESSED: tests 15+16 in `normalize-script.test.ts` round the
   fixtures through production `SceneSchema.parse()` to prove the
   adapter accepts known-valid production shape.
3. **Passthrough scene fields preserved only in `.raw`.** Intentional.
   `NormalizedScene` is a UI/prompt canonical subset; consumers needing
   `config_overrides`, `first_frame_versions`, etc. read raw scene
   directly (the existing pattern). Documented in `normalize-script.ts`
   module header.

## Future (1.8.0b)

The generator rewrite in 1.8.0b will introduce `narrative_paragraph` as
a first-class persisted field on `scene.script.scenes[]`. Once that
ships, the synthesised `narrative_paragraph` (defaulting via
`description_ru`) is replaced by the genuine field. No further behavior
shift.
