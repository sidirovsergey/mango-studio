# Phase 1.6 — Identity Foundation (design spec)

**Status:** approved 2026-05-17 (brainstorm session)
**Predecessor:** v1.5.1 (character dossier UX + script-gen error unmask)
**Successor:** Phase 1.7 = Payments (out of scope here)
**Target tag on ship:** `v1.6.0`

## 1. Motivation

`mangopro.ru` is live on Phase 1.5.1 with **anonymous-only** identity: middleware auto-runs `supabase.auth.signInAnonymously()` per visitor, projects are keyed on `auth.uid()`, cookie loss = project loss. There is no email, no password, no payments. F53 atomic rate-limit caps abuse per-user, but anonymous users are trivially reset by clearing cookies.

The original launch plan had Phase 2 = auth + payments as a single phase. After brainstorm we split:

- **1.6 = Identity Foundation** — email OTP login + claim flow for anon users + account-level capability tier (`trial` / `free` / `premium`).
- **1.7 = Payments** — billing provider, upgrade flow, webhooks (separate spec).

1.6 is purposefully scoped so the *enforcement layer* (tier gating) is already proven in production when payments are wired up in 1.7.

## 2. Goals & non-goals

**Goals**
- Email OTP login flow (6-digit code), no password, no OAuth.
- Anonymous users remain supported as **trial-tier** with strict capability gate.
- `linkIdentity` claim flow: anon UUID merges into email account, no project migration needed.
- Tier per-account: `trial` (anon), `free` (email), `premium` (1.7).
- Capability matrix enforced server-side at every video-generating action.
- Own SMTP on `mangopro.ru` for OTP emails.

**Non-goals (defer)**
- Payments / billing provider integration → 1.7.
- OAuth (Google/Yandex) → 1.6.5 if prod feedback demands it.
- Password auth → not planned.
- Cross-account project migration when email already exists → 1.7+ explicit CTA.
- Email change UI → 1.7+.
- Disposable email / one-time email blocking → 1.7 with billing.

## 3. Design

### 3.1 Architecture

**Supabase Auth configuration**
- Enable email provider, sign-up method = OTP (6-digit code, ~10 min TTL).
- Keep anonymous provider enabled (middleware unchanged).
- SMTP: custom `noreply@mangopro.ru` server, configured in Supabase Auth dashboard.
- **Pre-flight requirement:** verify SPF / DKIM / DMARC records for `mangopro.ru` to keep OTP emails out of spam. Real deliverability test (send to gmail.com, yandex.ru, mail.ru) before declaring ship.

**New table `user_accounts`** (1:1 extension of `auth.users`)
```sql
create table user_accounts (
  user_id uuid primary key references auth.users(id) on delete cascade,
  tier text not null check (tier in ('trial','free','premium')) default 'trial',
  email text,                          -- denormalized from auth.users
  display_name text,
  created_at timestamptz default now(),
  upgraded_to_free_at timestamptz,
  upgraded_to_premium_at timestamptz   -- reserved for 1.7
);

-- RLS: user can SELECT/UPDATE own row only
alter table user_accounts enable row level security;
create policy "own row r"  on user_accounts for select using (user_id = auth.uid());
create policy "own row w"  on user_accounts for update using (user_id = auth.uid());
```

**Auto-provisioning trigger** on `auth.users` insert:
- if `is_anonymous = true` → `user_accounts (user_id, tier) values (new.id, 'trial')`
- else → `tier='free'` (covers the cold /login flow without prior anon session)

**Upgrade trigger** on `auth.identities` insert where `provider='email'`:
- if `user_accounts.tier = 'trial'` for that user_id → update `tier='free'`, `upgraded_to_free_at=now()`, `email = new.identity_data->>'email'`

**RLS impact**: none. All existing tables (`projects`, `media_jobs`, `messages`, etc.) are keyed on `auth.uid()`. `linkIdentity` preserves the same UUID, so projects survive the claim transparently — no `owner_id` rewrite needed.

### 3.2 Capability matrix (the actual gate)

Capability gating is **binary by media-job kind**, not numeric. F53 per-user rate-limit stays as an orthogonal anti-abuse layer.

| Kind                          | trial | free | premium |
|-------------------------------|-------|------|---------|
| `script_generation` (LLM)     | ✅     | ✅    | ✅       |
| `character_dossier`           | ✅     | ✅    | ✅       |
| `character_avatar`            | ✅     | ✅    | ✅       |
| `character_reference_image`   | ✅     | ✅    | ✅       |
| `first_frame`                 | ✅     | ✅    | ✅       |
| `scene_video` (economy)       | ❌     | ✅    | ✅       |
| `scene_video` (premium model) | ❌     | ❌    | ✅ (1.7) |
| `master_clip`                 | ❌     | ✅    | ✅       |

> **NB:** the existing per-project `tier` field (`economy` / `premium`) is the **generation tier** = video model class. It is independent of the account tier. Project.tier remains; account.tier is new. Free accounts can keep economy as default but may switch a project to premium model class only after 1.7 unlocks premium account tier.

### 3.3 Components

**UI (new)**
- `/login` page — RSC + Client: single email input → "Получить код" → 6-digit code input → submit.
- `AccountMenu` in `TopBar` — email/avatar if logged in, "Войти / Сохранить работу" if anon. Dropdown: "Выйти".
- `ClaimWorkBanner` — non-dismissive band at top for anon users with ≥1 project: «У вас N проектов. Войдите, чтобы сохранить их и разблокировать видео.»
- `TierGateModal` — opens when trial user attempts a video action; CTA leads to `/login`.

**Server (new)**
- `packages/core/src/quota/tiers.ts`
  - `type AccountTier = 'trial' | 'free' | 'premium'`
  - `getAccountTier(supabase, userId): Promise<AccountTier>`
  - `assertCapability(tier: AccountTier, kind: MediaJobKind, modelTier?: 'economy'|'premium'): void` — throws `TierGateError`
  - `TierGateError extends Error { code:'tier_gate'; required_tier; current_tier; kind }`
- `apps/web/src/app/auth/login/page.tsx` + `actions/{sendOtp,verifyOtp,signOut}Action.ts`
  - `verifyOtpAction` detects active anon session and calls `linkIdentity` instead of plain `verifyOtp`.
- `apps/web/src/server/actions/*` — every video-generating server action calls `assertCapability` before submit, returns `{ ok:false, error }` (the 1.5.1 `*ClientAction` pattern).

**DB**
- New migration: `user_accounts` table, RLS policies, two triggers.

**Untouched**
- `middleware.ts` — keep `signInAnonymously` for new visitors.
- All existing RLS policies on `projects`, `media_jobs`, etc.

### 3.4 Data flow

**A. New visitor → anon → trial work**
```
Visit / → middleware: no session → signInAnonymously()
       → trigger inserts user_accounts(tier='trial')
       → user creates project, script, characters, dossier, first_frames ✅
       → clicks "Сгенерировать видео" in Stage 04
       → server-action assertCapability('trial','scene_video') throws
       → returns {ok:false, error:{code:'tier_gate'}}
       → UI opens TierGateModal → "Войти, чтобы разблокировать видео"
```

**B. Claim — anon → email account**
```
User clicks "Войти" (TopBar OR TierGateModal OR ClaimWorkBanner)
       → /login → sendOtpAction → Supabase emails 6-digit code via mangopro.ru SMTP
       → user enters code → verifyOtpAction:
            if (anon session active):
               supabase.auth.linkIdentity({provider:'email', token})
               → SAME user_id, new email identity row
               → DB trigger fires → user_accounts.tier='free'
            else (cold visit to /login):
               supabase.auth.verifyOtp({type:'email', token, email})
               → new auth.users row with email, tier='free'
       → redirect to / → projects intact, AccountMenu shows email
```

**C. Returning email user**
```
Visit / → middleware: cookie has email session → getUser() returns email user
       → AccountMenu shows email, ClaimWorkBanner suppressed
       → all video actions allowed (free-tier capability check passes)
```

### 3.5 Error handling

| Error                          | Surface                              | UI message                                                              |
|--------------------------------|--------------------------------------|-------------------------------------------------------------------------|
| `otp_expired`                  | `verifyOtpAction` result             | «Код устарел, запросите новый.»                                          |
| `over_email_send_rate_limit`   | `sendOtpAction` result               | «Слишком частые запросы. Попробуйте через минуту.»                       |
| `invalid_credentials`          | `verifyOtpAction` result             | «Неверный код, проверьте email.»                                         |
| `tier_gate`                    | any video server-action result       | TierGateModal opens with reason copy                                    |
| `email_already_linked`         | `verifyOtpAction` conflict on link   | «Email уже привязан к другому аккаунту. Войдите туда напрямую — anon-проекты останутся доступны при возврате на это устройство.» |
| SMTP 5xx                       | `sendOtpAction` server error         | «Не удалось отправить код. Попробуйте через минуту.» + Vercel log       |

All errors flow through the `{ok:false, error}` result-type pattern established in 1.5.1 — no Next.js RSC error mask.

### 3.6 Testing

**Unit (Vitest)**
- `getAccountTier()` over the `is_anonymous` × identities matrix.
- `assertCapability()` over full 3 × 7 (tiers × kinds) matrix incl. modelTier dimension for `scene_video`.
- `verifyOtpAction` mocked Supabase: (anon → link), (cold → new), (conflict), (expired), (rate-limit).

**Integration**
- `generateSceneVideoAction(trial_user)` → returns `{ok:false, error:{code:'tier_gate'}}`, does NOT write to `media_jobs`.
- `generateCharacterDossierAction(trial_user)` → succeeds (image kind).
- DB trigger: insert anon `auth.users` → `user_accounts(tier='trial')` exists.
- DB trigger: insert `auth.identities(provider='email')` for trial user → `user_accounts.tier='free'` + `upgraded_to_free_at` set.

**E2E live smoke** (manual pre-ship per `feedback_live_smoke_before_ship_declaration`)
- Cold visit → `/login` → OTP → code arrives from `noreply@mangopro.ru` to gmail / yandex / mail.ru inbox (NOT spam).
- Anon → `/login` → `linkIdentity` → projects still visible after login.
- Trial → attempts video → TierGateModal opens, no media_jobs row.
- Free → attempts video → succeeds, media_jobs row written.

## 4. Risks & mitigations

| Risk                                                                     | Mitigation                                                                                                                                                              |
|--------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| OTP emails go to spam from `mangopro.ru`                                  | Pre-flight SPF/DKIM/DMARC validation + live inbox test to 3+ providers before declaring ship                                                                            |
| `linkIdentity` conflict locks users out of anon work                      | Clear error copy + retain anon session in cookies so user can come back to that device; explicit «Перенести проекты» CTA deferred to 1.7+                                |
| Trial gate breaks for a returning anon who had been free before            | Tier is per-account, not per-session; if cookie cleared, returning visitor is a NEW anon user_id → starts fresh. Acceptable trade-off (anon ≠ persistent identity).      |
| Existing prod users (all anon today) suddenly hit trial-tier wall on video | Backfill query in migration assigns `tier='free'` only to non-anon; all current users are anon → all become `trial`. **By design** — user must claim to keep video access. This is the conversion event. |
| F53 + tier gate double-error confuses users                                | Tier gate fires FIRST (early in action), F53 only on insert. User sees only one error.                                                                                  |
