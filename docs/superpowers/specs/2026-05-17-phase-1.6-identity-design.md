# Phase 1.6 — Identity Foundation (design spec)

**Status:** approved 2026-05-17 (brainstorm session)
**Predecessor:** v1.5.1 (character dossier UX + script-gen error unmask)
**Successor:** Phase 1.7 = Payments (out of scope here)
**Target tag on ship:** `v1.6.0`

## 1. Motivation

`mangopro.ru` is live on Phase 1.5.1 with **anonymous-only** identity: middleware auto-runs `supabase.auth.signInAnonymously()` per visitor, projects are keyed on `auth.uid()`, cookie loss = project loss. There is no email, no password, no payments. F53 atomic rate-limit caps abuse per-user, but anonymous users are trivially reset by clearing cookies.

The original launch plan had Phase 2 = auth + payments as a single phase. After brainstorm we split:

- **1.6 = Identity Foundation** — email OTP login + claim flow for anon users + account-level capability tier (`trial` / `free` / `premium`).
- **1.7 = Payments** — billing provider, upgrade flow, webhooks (separate spec).

1.6 is purposefully scoped so the *enforcement layer* (tier gating) is already proven in production when payments are wired up in 1.7.

## 2. Goals & non-goals

**Goals**
- Email OTP login flow (6-digit code), no password, no OAuth.
- Anonymous users remain supported as **trial-tier** with strict capability gate.
- Claim flow via `updateUser({ email })` + `verifyOtp(type='email_change')`: anon UUID is preserved (Supabase flips `is_anonymous` to false on the same row), no project migration needed.
- Tier per-account: `trial` (anon), `free` (email), `premium` (1.7).
- Capability matrix enforced server-side at every video-generating action.
- Own SMTP on `mangopro.ru` for OTP emails.

**Non-goals (defer)**
- Payments / billing provider integration → 1.7.
- OAuth (Google/Yandex) → 1.6.5 if prod feedback demands it.
- Password auth → not planned.
- Cross-account project migration when email already exists → 1.7+ explicit CTA.
- Email change UI → 1.7+.
- Disposable email / one-time email blocking → 1.7 with billing.

## 3. Design

### 3.1 Architecture

**Supabase Auth configuration**
- Enable email provider, sign-up method = OTP (6-digit code, ~10 min TTL).
- Keep anonymous provider enabled (middleware unchanged).
- SMTP: custom `noreply@mangopro.ru` server, configured in Supabase Auth dashboard.
- **Pre-flight requirement:** verify SPF / DKIM / DMARC records for `mangopro.ru` to keep OTP emails out of spam. Real deliverability test (send to gmail.com, yandex.ru, mail.ru) before declaring ship.

**New table `user_accounts`** (1:1 extension of `auth.users`)
```sql
create table user_accounts (
  user_id uuid primary key references auth.users(id) on delete cascade,
  tier text not null check (tier in ('trial','free','premium')) default 'trial',
  email text,                          -- denormalized from auth.users
  display_name text,
  created_at timestamptz default now(),
  upgraded_to_free_at timestamptz,
  upgraded_to_premium_at timestamptz   -- reserved for 1.7
);

-- RLS: clients can read/update own row; INSERT and DELETE are denied.
-- All writes happen through SECURITY DEFINER trigger functions.
alter table user_accounts enable row level security;
create policy "own row select" on user_accounts for select using (user_id = auth.uid());
create policy "own row update" on user_accounts for update using (user_id = auth.uid());
-- (no insert/delete policy = denied by default with RLS on)
```

**Auto-provisioning trigger** on `auth.users` insert (`SECURITY DEFINER`, `set search_path = '', pg_catalog, public`, owned by `postgres`):
- if `new.is_anonymous = true` → `insert into user_accounts (user_id, tier) values (new.id, 'trial') on conflict do nothing`
- else → `tier='free'` + `email=new.email`

**Upgrade trigger** on `auth.identities` insert where `new.provider='email'` (`SECURITY DEFINER`, same `search_path` discipline):
- guard: `if (select tier from user_accounts where user_id = new.user_id) = 'trial' then`
  - `update user_accounts set tier='free', upgraded_to_free_at=now(), email=new.identity_data->>'email' where user_id=new.user_id`
- guard means: a `free` user adding a second email identity later is a no-op; a `premium` user is untouched; the cold-OTP path (which fires both triggers in the same transaction) is also safe because the first trigger already set `tier='free'`.

**RLS impact**: none. All existing tables (`projects`, `media_jobs`, `messages`, etc.) are keyed on `auth.uid()`. The anon→email conversion via `updateUser({ email })` + `verifyOtp(type='email_change')` preserves the same `user.id`, so projects survive the claim transparently — no `owner_id` rewrite needed.

### 3.2 Capability matrix (the actual gate)

Capability gating is **binary by media-job kind**, not numeric. F53 per-user rate-limit stays as an orthogonal anti-abuse layer.

**Source of truth for kinds** = the DB constraint in `supabase/migrations/20260512000001_phase_1_4_add_character_reference_image_kind.sql`. The `MediaJobKind` TS type in `apps/web/src/server/lib/scene-helpers.ts` is stale (10 of 14 kinds — `character_reference_image`, `scene_first_frame`, `scene_video`, `scene_voice`, `scene_final_clip`, `storage_mirror` missing). **Align TS type with DB in 1.6 as a prerequisite task** (called out in the plan).

**Categorisation** (relative to the tier gate):

| Kind family                      | DB kinds                                                                                                        | Tier-gate role                                                                                                                                                |
|----------------------------------|------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Character images                 | `character_dossier`, `character_avatar`, `character_reference`, `character_reference_image`                       | **Allowed for all tiers** (trial, free, premium). User-callable.                                                                                              |
| Scene first frame                | `first_frame` (legacy 1.3.0), `scene_first_frame` (1.3.5)                                                         | **Allowed for all tiers.** User-callable.                                                                                                                     |
| Scene video                      | `video` (legacy 1.3.0), `scene_video` (1.3.5)                                                                     | **Blocked for trial.** Free + premium allowed; premium-model-class submodels still blocked for free (deferred to 1.7). User-callable.                          |
| Master clip                      | `master_clip`                                                                                                    | **Blocked for trial** (free + premium allowed). User-callable.                                                                                                |
| Legacy audio (v1.5.0 rip-out)    | `voice`, `scene_voice`, `final_clip`, `scene_final_clip`                                                          | **Hard-disabled at the action layer** regardless of tier. Polling kept for back-compat with historic rows; no new user-callable entry points. Tier gate N/A.   |
| Internal infra                   | `last_frame_extract`, `storage_mirror`                                                                            | **No tier gate.** Server-side chain only (fired automatically), never user-callable.                                                                          |
| LLM (not a media_jobs kind)      | `script_generation` lives in `llm_calls`, not `media_jobs`                                                       | **Allowed for all tiers.** Distinct enforcement surface — call sites are `generateScriptAction` / `regenScriptAction` / `refineScriptAction` / `refineBeatAction`. Tier check only needed if a future enforcement wants to gate LLM cost. **Not gated in 1.6.** |

> **NB:** the existing per-project `tier` field (`economy` / `premium`) is the **generation tier** = video model class. It is independent of the account tier. Project.tier remains; account.tier is new. Free accounts can keep economy as default but may switch a project to premium model class only after 1.7 unlocks premium account tier. The `modelTier?: 'economy'|'premium'` parameter of `assertCapability` is the seam where the per-project tier is checked against the per-account tier for `scene_video` / `video` / `master_clip`.

### 3.3 Components

**UI (new)**
- `/login` page (canonical path) — RSC + Client: single email input → "Получить код" → 6-digit code input → submit. File: `apps/web/src/app/login/page.tsx`. Spec previously suggested `app/auth/login` — **canonical is `app/login`** to match the UX URL.
- `AccountMenu` in `TopBar` — email/avatar if logged in, "Войти / Сохранить работу" if anon. Dropdown: "Выйти". Optional: anon-user project count as a motivator (see Open Q in §5).
- `ClaimWorkBanner` — non-dismissive band at top for anon users with ≥1 project: «У вас N проектов. Войдите, чтобы сохранить их и разблокировать видео.»
- `TierGateModal` — opens when trial user attempts a video action; CTA leads to `/login`.

**Server (new)**
- `packages/core/src/quota/tiers.ts`
  - `type AccountTier = 'trial' | 'free' | 'premium'`
  - `getAccountTier(supabase, userId): Promise<AccountTier>`
  - `assertCapability(tier: AccountTier, kind: MediaJobKind, modelTier?: 'economy'|'premium'): void` — throws `TierGateError`
  - `TierGateError extends Error { code:'tier_gate'; required_tier; current_tier; kind }`
- `apps/web/src/app/login/page.tsx` + `actions/{sendOtp,verifyOtp,signOut}Action.ts`
  - **`verifyOtpAction` branches by session state:**
    - If `auth.getUser()` returns an anonymous user → previously `sendOtpAction` called `supabase.auth.updateUser({ email })` (which queues an email-change OTP); now `verifyOtpAction` calls `supabase.auth.verifyOtp({ email, token, type: 'email_change' })`. Same `user.id`, `is_anonymous` flips to false, the new `auth.identities` email row triggers the DB trigger → `user_accounts.tier='free'`.
    - If no anon session (cold visit) → previously `sendOtpAction` called `supabase.auth.signInWithOtp({ email })`; now `verifyOtpAction` calls `supabase.auth.verifyOtp({ email, token, type: 'email' })`. Creates a new `auth.users` with `is_anonymous=false`, the on_users_insert trigger creates `user_accounts(tier='free')`.
  - **NB:** `supabase.auth.linkIdentity` is for OAuth providers, NOT for email — the previous spec draft was wrong. The email-conversion path is `updateUser({ email })` per Supabase Anonymous-Sign-Ins docs.
- `apps/web/src/server/actions/*` — every user-callable video-generating server action calls `assertCapability` **before** the existing `reserveMediaJob` call (where F53 atomic reservation lives), returns `{ ok:false, error }` (the 1.5.1 `*ClientAction` pattern). Specifically:
  - `generateSceneVideoAction.ts:208-215` — single-scene path
  - `generateFirstFrameAction.ts:273-281` — bulk-first-frame path that fan-outs to scene_video
  - `generateMasterClipAction.ts:147-155`
  - **Not gated** (image kinds): `generateCharacterDossierAction.ts`, `generateReferenceImageAction.ts`, `generateFirstFrameAction.ts` single-scene path. (First frame is an image, not a video.)

**DB**
- New migration `20260518000001_user_accounts.sql`: table + RLS (clients may SELECT/UPDATE own row e.g. for `display_name`; INSERT/DELETE denied — provisioning + tier upgrades happen via `SECURITY DEFINER` triggers) + 2 triggers, both `SECURITY DEFINER`:
  - `tg_user_accounts_provision_on_auth_users_insert` — after insert on `auth.users`, inserts a `user_accounts` row keyed by `new.id`, `tier='trial'` if `new.is_anonymous=true` else `'free'`.
  - `tg_user_accounts_upgrade_on_email_identity` — after insert on `auth.identities` where `new.provider='email'`, sets `user_accounts.tier='free'` and `upgraded_to_free_at=now()` **only if current tier is `'trial'`** (idempotent guard — a free user adding a second email identity later does not regress; a premium user is unaffected).
  - Both functions `set search_path = '', pg_catalog, public` per existing project convention (`supabase/migrations/20260516000004_media_jobs_atomic_quota_v4.sql:42-45`).

**Untouched**
- `middleware.ts` — keep `signInAnonymously` for new visitors. **The `/login` route is matched by the middleware**, so a cold visitor lands on `/login` already anon. Consequence: the cold-OTP path (`signInWithOtp`) is rarely reached in practice — the conversion path (`updateUser` → `verifyOtp type=email_change`) is the primary flow. We keep the cold branch as a safety net for users who clear cookies between `sendOtpAction` and `verifyOtpAction`, and for users who explicitly sign out then return.
- All existing RLS policies on `projects`, `media_jobs`, etc. `auth.uid()` stays stable across the anon→email conversion → no policy changes needed.

### 3.4 Data flow

**A. New visitor → anon → trial work**
```
Visit / → middleware: no session → signInAnonymously()
       → trigger inserts user_accounts(tier='trial')
       → user creates project, script, characters, dossier, first_frames ✅
       → clicks "Сгенерировать видео" in Stage 04
       → server-action assertCapability('trial','scene_video') throws
       → returns {ok:false, error:{code:'tier_gate'}}
       → UI opens TierGateModal → "Войти, чтобы разблокировать видео"
```

**B. Claim — anon → email account**
```
User clicks "Войти" (TopBar OR TierGateModal OR ClaimWorkBanner)
       → /login → sendOtpAction branches by session:
            if (anon session active):  [PRIMARY PATH — middleware ensures this in practice]
               supabase.auth.updateUser({ email })
               → queues an email-change OTP, sent via mangopro.ru SMTP
            else (cookies cleared / explicit signed out):
               supabase.auth.signInWithOtp({ email })
               → cold-signup OTP sent via mangopro.ru SMTP
       → user receives 6-digit code → enters it → verifyOtpAction:
            if (anon session active):
               supabase.auth.verifyOtp({ email, token, type: 'email_change' })
               → SAME user_id, is_anonymous flips to false,
                 new auth.identities row (provider=email)
               → DB trigger tg_user_accounts_upgrade_on_email_identity:
                 user_accounts.tier='free', upgraded_to_free_at=now()
            else (cold):
               supabase.auth.verifyOtp({ email, token, type: 'email' })
               → new auth.users row with email, is_anonymous=false
               → DB trigger tg_user_accounts_provision_on_auth_users_insert:
                 user_accounts(tier='free')
       → redirect to / → projects intact (anon path) OR no projects (cold path)
       → AccountMenu shows email
```

**UUID guarantee** — `same user.id only when converting the active anonymous session via `updateUser({ email })`. The cold path creates a NEW `user.id` and any projects from a prior anon session on the same browser remain owned by the abandoned anon UUID (still selectable via that anon cookie if it ever returns; orphaned otherwise). Spec'd as acceptable for 1.6 MVP.

**C. Returning email user**
```
Visit / → middleware: cookie has email session → getUser() returns email user
       → AccountMenu shows email, ClaimWorkBanner suppressed
       → all video actions allowed (free-tier capability check passes)
```

### 3.5 Error handling

| Error                          | Surface                              | UI message                                                              |
|--------------------------------|--------------------------------------|-------------------------------------------------------------------------|
| `otp_expired`                  | `verifyOtpAction` result             | «Код устарел, запросите новый.»                                          |
| `over_email_send_rate_limit`   | `sendOtpAction` result               | «Слишком частые запросы. Попробуйте через минуту.»                       |
| `invalid_credentials`          | `verifyOtpAction` result             | «Неверный код, проверьте email.»                                         |
| `tier_gate`                    | any video server-action result       | TierGateModal opens with reason copy                                    |
| `email_already_taken`          | `updateUser({ email })` from anon when email already belongs to another user_id | «Email уже привязан к другому аккаунту. Выйдите и войдите туда напрямую — anon-проекты на этом устройстве сохранятся под cookie.» Plan must include explicit «Sign out + retry as cold» helper. |
| SMTP 5xx / SMTP rate limit     | `sendOtpAction` server error         | «Не удалось отправить код. Попробуйте через минуту.» + Vercel log       |

**SMTP rate limits — quantified**

- **Supabase Auth built-in:** by default ~30 OTP/hour per project on the shared Supabase SMTP. With custom SMTP, Supabase still enforces a per-email rate-limit (configurable in Auth → Rate Limits dashboard; default 2 OTPs per email per 60s). Set this explicitly to a documented value before ship (suggest 1 OTP/60s per email + 5 OTP/15min per email).
- **mangopro.ru SMTP capacity floor (target):** at minimum 200 OTP-emails/hour sustained, 500 burst/hour. Below that, the OTP flow will throttle real users at launch (estimated ~50-100 OTPs/day in first month based on prior traffic, but spikes during marketing pushes can 10x the baseline). Owner must document the actual hourly send cap of the chosen `smtp.mangopro.ru` infra and confirm it meets the floor before ship. If shared with marketing/transactional, isolate `noreply@mangopro.ru` to its own throttle bucket.
- **Per-IP throttling at the action layer:** add a lightweight rate-limit on `sendOtpAction` (e.g. 5 sends per 10 min per IP via Supabase `_request_log` or Vercel KV) to defend against enumeration attacks if the Supabase per-email limit isn't hit first.

All errors flow through the `{ok:false, error}` result-type pattern established in 1.5.1 — no Next.js RSC error mask.

**Tier-gate placement vs F53 race** — `assertCapability` runs **before** `reserveMediaJob` (the atomic-quota path). The tier is read from `user_accounts` in the same server-action; if a user upgrades from free→premium concurrently with two scene_video submits, "last committed tier wins" — both submits read tier-at-call-time and act on it. Worst case: a brief race where a just-upgraded user gets a tier_gate error and retries (and succeeds). Acceptable.

   - Trigger ownership: created by `postgres` role so they bypass RLS on `user_accounts` insert/update.
   - Backfill: `insert into user_accounts (user_id, tier) select id, case when is_anonymous then 'trial' else 'free' end from auth.users on conflict do nothing;` (or the identities-derived variant from step 0).
2. **Pre-seed owner accounts** to avoid tier-lockout on first deploy:
   - Identify Sergey's anon user_id from prod (`select id from auth.users where ... order by created_at desc limit ...` or via project ownership lookup). 3. SMTP setup on Supabase Auth dashboard:
   - Custom SMTP: host/port/creds for `noreply@mangopro.ru`.
   - Auth → Rate Limits: OTP per email = 1/60s + 5/15min (suggested defaults).

5. Apply migration via Supabase MCP (`apply_migration`) to prod — verify with `list_migrations` per `feedback_supabase_migration_deploy_gap`.
6. Deploy to Vercel with flag off, observe logs for 30+ min.
7. Flip flag on (Vercel env var → redeploy).
8. Live smoke on `mangopro.ru` per checklist above.
9. Tag `v1.6.0`.

## 4. Risks & mitigations

| Risk                                                                     | Mitigation                                                                                                                                                              |
|--------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| OTP emails go to spam from `mangopro.ru`                                  | Pre-flight SPF/DKIM/DMARC validation + live inbox test to 3+ providers before declaring ship                                                                            |
| `updateUser({ email })` conflict (email already taken) locks user out of anon work | Clear error copy + retain anon session in cookies so user can come back to that device; explicit «Перенести проекты» CTA deferred to 1.7+                                |
| Trial gate breaks for a returning anon who had been free before            | Tier is per-account, not per-session; if cookie cleared, returning visitor is a NEW anon user_id → starts fresh. Acceptable trade-off (anon ≠ persistent identity).      |
| Existing prod users (all anon today) suddenly hit trial-tier wall on video | Backfill assigns `tier='free'` only to non-anon; all current users are anon → all become `trial`. **By design** — user must claim to keep video access. This is the conversion event. **Owner (Sergey) is pre-seeded `tier='free'` in rollout step 2 of §3.7** to keep E2E testing unblocked. |
| Spec-level capability matrix drifts from DB constraint when a new kind is added | Plan adds the TS-type alignment task as prerequisite (§5a) AND a Vitest test that asserts every value in `MediaJobKind` appears in `assertCapability`'s switch — fails-loud on the next kind addition. |
| F53 + tier gate double-error confuses users                                | Tier gate fires FIRST (early in action), F53 only on insert. User sees only one error.                                                                                  |
