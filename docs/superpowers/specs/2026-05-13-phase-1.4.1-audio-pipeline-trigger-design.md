# Phase 1.4.1 — Audio pipeline trigger (design spec)

**Status:** draft · 2026-05-13
**Predecessor:** [v1.4.0](../../phase-1.4-prompt-refactor/01-architecture.md) — prompt refactor across all 6 AI surfaces. v1.4.0 shipped on 2026-05-12 as commit `8d23f92`.
**Bug:** generated videos are silent for ALL Russian-dialogue scenes despite a fully-wired voice + mux backend.

## 1. Problem statement

Russian-dialogue scenes follow the F32 design (Phase 1.3.5): video model generates silent video, ElevenLabs TTS produces voice audio separately, ffmpeg-api muxes them per scene, then master clip stitches per-scene clips. Cyrillic detection in `packages/core/src/media/audio-mode.ts:resolveAudioMode` forces `silent_tts` for any Cyrillic text.

Three actions exist in `apps/web/src/server/actions/`:

1. **`generateSceneVoiceAction.ts`** — ElevenLabs TTS for `scene.dialogue.text`, stores in `scene.voice_audio_versions[]`.
2. **`composeSceneFinalClipAction.ts`** — `fal-ai/ffmpeg-api` muxes active `video` + active `voice_audio` into `scene.final_clip`.
3. **`generateMasterClipAction.ts`** — stitches scenes' `final_clip` (preferred) or `video` (silent fallback) into `master_clip_versions[]`.

Grep confirms (1) and (2) are referenced ONLY in their own test files — no UI component, no Director chat tool, no webhook chain. `pollMediaJobsAction.ts:214,257` handles `voice` and `final_clip` job-result writes correctly — only the trigger is missing. `generateMasterClipAction.ts:84-110` silently falls back to silent video when `final_clip` is absent. `Stage04Inline.tsx:67` enables the "Финализировать ролик" button as soon as video exists, regardless of voice/mux state.

Net effect: user clicks Текст → Кадр → Видео → Финализировать ролик → silent master clip.

## 2. Design decisions (locked through brainstorm 2026-05-13)

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | **Auto-chain in `pollMediaJobsAction`** triggers voice and final_clip jobs reactively. No new buttons, no webhooks. | Pipeline already exists; only the trigger missing. Poll-loop already has RLS-aware `recordPendingJob`, user/project context, and Realtime propagation. |
| D2 | **Cumulative cost hint on the «Видео» action tile.** Russian scenes show `$0.30 + $0.06 озвучка` instead of bare `$0.30`. | Honesty before generation; surfaces the auto-chain cost without blocking. |
| D3 | **Inline scene player shows only `final_clip`.** Spinner while voice/mux pending; raw video hidden once chain starts. | Single source of truth for "what the scene actually sounds like". Avoids confusion of two playable assets per scene. |
| D4 | **«Финализировать ролик» readiness = all videos exist.** If user clicks before voice/mux complete → confirm dialog: «Дождаться (~2 мин)» or «Склеить без звука». | Preserves current zero-friction UX for English scenes; explicit consent for silent fallback on Russian. |
| D5 | **`audio_mode` user override always wins.** `silent_tts` forces TTS; `native` skips TTS even on Cyrillic; `auto` uses `resolveAudioMode`. | Trust user intent; existing schema; no migration. |
| D6 | **Auto-retry once with 15 s backoff** for voice / final_clip failures, then leave failed-state with manual retry button. | Covers ElevenLabs rate limits + transient ffmpeg failures without exponential complexity. |
| D7 | **Two new Director chat tools:** `regen_scene_voice`, `compose_scene_final_clip`. | Symmetry with `regen_scene_video`; enables chat-driven voice override ("озвучь сцену 3 другим голосом"). |
| D8 | **`has_full_audio: boolean`** stamped on each `master_clip_versions[]` entry. Badge in Stage 05 player. | User sees whether the master they're watching is the "with audio" or "silent fallback" version. |

## 3. Architecture

### 3.1 Auto-chain core

New module: `packages/core/src/media/audio-chain.ts` with a single pure function:

```ts
type Scene = { /* ... existing SceneShape ... */ };
type Dialogue = { speaker: string; text: string } | null;

type ChainStep =
  | null
  | { kind: 'voice' }
  | {
      kind: 'final_clip';
      video_version_id: string;
      voice_audio_version_id: string;
    };

export function planNextChainStep(scene: Scene, dialogue: Dialogue): ChainStep;
```

**Logic:**

1. If no `dialogue.text` (empty/missing) → return `null` (nothing to voice).
2. Compute `mode = resolveAudioMode(scene, dialogue)`.
3. If `mode === 'native'` → return `null` (model produces audio itself).
4. If `mode === 'silent_tts'`:
   - If no active video version → return `null` (chain hasn't reached this step yet).
   - If no active voice version → return `{ kind: 'voice' }`.
   - If `final_clip` is missing OR its `composed_from` is stale relative to active video/voice version IDs → return `{ kind: 'final_clip', ... }`.
   - Otherwise → return `null` (chain complete).

Unit-tested against the full matrix in `audio-chain.test.ts`.

### 3.2 Poll-loop integration

In `pollMediaJobsAction.ts`, after the existing per-kind result-write blocks (`video`, `voice`, `final_clip`), insert a unified chain-advancement step:

```ts
// After updating script for the succeeded job, plan the next chain step
// for the affected scene (if any) and enqueue it via recordPendingJob.
if (job.scene_id && job.kind in ('video', 'voice')) {
  const scene = nextScript.scenes.find(s => s.scene_id === job.scene_id);
  if (scene) {
    const step = planNextChainStep(scene, scene.dialogue ?? null);
    if (step) {
      await recordPendingJob({
        user_id: job.user_id,
        project_id: job.project_id,
        scene_id: job.scene_id,
        kind: step.kind === 'voice' ? 'voice' : 'final_clip',
        model: /* resolved per kind */,
        fal_request_id: /* from new submit call */,
        request_input: /* per-kind input */,
      });
    }
  }
}
```

The actual submit-to-fal call is delegated to the existing actions:
- For `voice` → re-use the `getMediaProvider().submitVoiceTTS(...)` path from `generateSceneVoiceAction`. Factor out a thin helper `submitVoiceJob(ctx, scene, dialogue)` that both the action and poll-loop can call.
- For `final_clip` → analogous helper `submitFinalClipJob(ctx, scene, video_version_id, voice_audio_version_id)`.

Helpers live in `apps/web/src/server/lib/audio-chain-helpers.ts`. Each takes Supabase row data + ctx, returns `{ job_id, existing }` via `recordPendingJob`. The poll-loop and Director tools both call these — no duplicated submit logic.

**Idempotency:** `recordPendingJob` already deduplicates on `(user_id, project_id, scene_id, kind, request_input fingerprint)` per Phase 1.3. Poll-loop firing twice (double-realtime) returns `existing: true`, no double charge.

### 3.3 Failure handling + retry

**Schema migration** `supabase/migrations/20260513000001_phase_1_4_1_audio_chain.sql`:

```sql
ALTER TABLE media_jobs
  ADD COLUMN retry_count INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN delayed_until TIMESTAMPTZ NULL;

CREATE INDEX media_jobs_delayed_until_idx ON media_jobs (delayed_until)
  WHERE delayed_until IS NOT NULL;
```

**Poll-loop changes:**

- The poll query skips rows where `delayed_until > now()` (filter in the WHERE clause).
- When a `voice` or `final_clip` job arrives `failed` from fal.ai:
  - If `retry_count < 1` → call `recordPendingJob` with identical `request_input` + `delayed_until = now() + interval '15 seconds'` and increment `retry_count` on the new row. The old failed row stays for audit.
  - If `retry_count >= 1` → leave failed; UI surfaces retry button.

**Manual retry action:** `retrySceneAudioAction(project_id, scene_id, kind: 'voice' | 'final_clip')` — calls the relevant helper with `retry_count = 0`, fresh `delayed_until = null`. Wired to the failure-state player button.

### 3.4 Director chat tools

Two new tools in `apps/web/src/server/lib/director-tools.ts`, following the pattern of `regen_scene_video` and `rollback_scene_version`.

**`regen_scene_voice`**

```ts
{
  name: 'regen_scene_voice',
  description: 'Regenerate the voice audio for a specific scene. Use when the user wants a different voice, different text reading, or to retry after a failure.',
  parameters: {
    scene_id: z.string(),
    voice_id: z.string().optional(),       // override character/narrator default
    text_override: z.string().optional(),  // override script dialogue text
  },
  confirm_required: true,
  cost_hint_usd: 0.05,
}
```

Implementation: validates scene exists and has dialogue (or `text_override` provided). Calls `submitVoiceJob` with overrides. The poll-loop subsequently picks up the new voice and auto-chains to `final_clip`.

**`compose_scene_final_clip`**

```ts
{
  name: 'compose_scene_final_clip',
  description: 'Recompose the final clip for a scene from current active video + voice versions. Use after rollback_scene_version on voice or video to refresh the final_clip.',
  parameters: { scene_id: z.string() },
  confirm_required: true,
  cost_hint_usd: 0.01,
}
```

Implementation: requires active video AND active voice_audio version. Calls `submitFinalClipJob`. No further chaining.

**Director state summary** (`packages/core/src/llm/director-state-summary.ts`): add per-scene field `final_clip_stale: boolean` — `true` if `final_clip.composed_from.video_version_id !== video_active_version_id` or `final_clip.composed_from.voice_audio_version_id !== voice_audio_active_version_id`. Lets Director proactively suggest `compose_scene_final_clip` after a `rollback_scene_version` on voice.

## 4. UI changes

### 4.1 `SceneSidePanel.tsx` — video tile cost hint

Augment `videoCostHint` calculation. For scenes where:

- `resolveAudioMode(scene, scene.dialogue) === 'silent_tts'` AND
- `scene.dialogue?.text` is non-empty

…append ` + $0.06 озвучка` to the cost label.

New constant in `@mango/core`:

```ts
export const AUDIO_CHAIN_COST_HINT_USD = 0.06; // ~$0.05 TTS + ~$0.01 mux
```

### 4.2 `SceneThumbnailColumn.tsx` — inline player priority

Replace current `activeVideo.storage.url` source with priority chain:

1. `scene.final_clip` exists → play final clip (URL via `urlOfStorage`).
2. Active `voice` or `final_clip` job is `pending|running` for this scene → render `<AudioPipelineSpinner kind={job.kind} />` (label: «озвучка готовится…» for voice, «собираю финал…» for final_clip).
3. Active `voice` or `final_clip` job is `failed` with `retry_count >= 1` → render `<AudioPipelineError onRetry={() => retrySceneAudioAction(...)} />`.
4. `activeVideo` exists → play raw video (current behavior — Latin / native scenes / legacy).
5. Otherwise placeholder (current behavior).

Badge in the corner:
- `final_clip` present → 🎵 «со звуком»
- `audio_mode === 'native'` and `activeVideo.has_native_audio` → 🎵 «native»
- `audio_mode === 'native'` and not `has_native_audio` → 🔇 «silent»
- Otherwise (chain in progress) → no badge

### 4.3 `Stage04Inline.tsx` — finalize button + dialog

**Readiness logic** (replaces current `isSceneReady`):

```ts
const isSceneVideoReady = (s) => s.video_active_version_id !== null;
const isSceneFinalReady = (s) =>
  s.final_clip !== null ||
  resolveAudioMode(s, s.dialogue ?? null) === 'native';

const allVideosReady = scenes.every(isSceneVideoReady);
const allFinalsReady = scenes.length > 0 && scenes.every(isSceneFinalReady);
```

Button enables when `allVideosReady` (unchanged externally), but click-behavior splits:

- If `allFinalsReady` → call `generateMasterClipAction` directly (current path).
- Else → open `<FinalizeConfirmDialog>` showing per-scene status (chain in progress / chain failed / ready) with two buttons: «Дождаться (~2 мин)» and «Склеить без звука».

`<FinalizeConfirmDialog>`:
- Subscribes to the same `jobs` array via `useStage04`.
- «Дождаться» disables itself while not `allFinalsReady`; auto-runs `generateMasterClipAction` once everything's ready.
- «Склеить без звука» calls `generateMasterClipAction` immediately; silent-fallback path in the action runs as-is.
- Scenes in `failed` retry-exhausted state show their state inline with a deep-link to "Stage 04 → scene N" so user can retry.

### 4.4 Stage 05 — `has_full_audio` badge

In the master player view (the existing inline player from Phase 1.3.5 PR #17), under the video element add:

```tsx
{activeMaster.has_full_audio === true && (
  <span className="master-audio-badge ok">🎵 со звуком</span>
)}
{activeMaster.has_full_audio === false && (
  <span
    className="master-audio-badge warn"
    title="Часть сцен не озвучена. Вернись в Stage 04, доозвучь и пересобери ролик."
  >
    🔇 без звука
  </span>
)}
{/* undefined → no badge (legacy masters from before this fix) */}
```

### 4.5 `AudioModeControl` — no UI change

Existing control (`auto / native / TTS`) is unchanged. Its semantics become "real" — `silent_tts` now actually causes TTS to run; `native` now actually skips it.

## 5. Master clip behavior

`generateMasterClipAction.ts` itself does NOT change. Existing logic:

- For each scene: prefer `final_clip`, fall back to active video, fail if neither.
- Submit master concat to fal-ai/ffmpeg-api.

What changes is the **caller context** + **what we record**:

- New field on each `master_clip_versions[]` entry: `has_full_audio: boolean`.
- Computed in `generateMasterClipAction` BEFORE submit, then passed inside the existing `request_input` payload (it already carries `composed` per `generateMasterClipAction.ts:130-134`):
  ```ts
  const has_full_audio = resolved.every(r =>
    r.voice_audio_version_id !== null ||
    /* native scene contributes via raw video which has native audio */
    sceneIsNativeWithAudio(scriptScene)
  );
  // ...
  request_input: { ...(handle.request_input ?? {}), composed, has_full_audio }
  ```
- The poll-loop's `kind === 'master_clip'` write block (already exists in `pollMediaJobsAction`) reads `requestInput.has_full_audio` and copies it onto the new `master_clip_versions[]` entry alongside `generated_at`, `cost_usd`, etc.
- Legacy master rows (pre-fix) have `has_full_audio === undefined` → Stage 05 shows no badge.

## 6. Migration & data model

| Change | Scope | Backward compat |
|--------|-------|-----------------|
| `media_jobs.retry_count INTEGER NOT NULL DEFAULT 0` | New column | Existing rows default to 0 |
| `media_jobs.delayed_until TIMESTAMPTZ NULL` | New column | NULL = no delay (matches old behavior) |
| `media_jobs_delayed_until_idx` partial index | Performance | Empty initially |
| `master_clip_versions[].has_full_audio: boolean \| undefined` | Inside `projects.script` jsonb | Old records have field missing → UI treats as undefined |
| `final_clip.composed_from.voice_audio_version_id: string \| null` | Inside `projects.script` jsonb (already exists per `generateMasterClipAction.ts:21`) | Already nullable |

Additive migration; no destructive changes. Revert PR safely rolls back without rolling back SQL (columns just become unused).

## 7. Testing strategy

### 7.1 Unit tests

- `packages/core/src/media/audio-chain.test.ts` — `planNextChainStep` against the full matrix:
  - Cyrillic + auto + no video yet → `null`
  - Cyrillic + auto + video + no voice → `{ kind: 'voice' }`
  - Cyrillic + auto + video + voice + no final_clip → `{ kind: 'final_clip', ... }`
  - Cyrillic + auto + video + voice + final_clip stale (composed_from differs) → `{ kind: 'final_clip', ... }`
  - Cyrillic + auto + video + voice + final_clip fresh → `null`
  - Cyrillic + `audio_mode: 'native'` + video → `null`
  - Latin + auto (resolves to native) + video → `null`
  - Latin + `audio_mode: 'silent_tts'` + video → `{ kind: 'voice' }`
  - Empty dialogue → `null`

### 7.2 Integration tests

- `pollMediaJobsAction.test.ts` — extend existing tests:
  - video succeeded + Cyrillic dialogue → voice job enqueued
  - video succeeded + audio_mode=native → no voice job
  - voice succeeded → final_clip job enqueued
  - final_clip succeeded → no further job
  - voice failed retry_count=0 → new voice job with retry_count=1 + delayed_until
  - voice failed retry_count=1 → no new job, row stays failed
  - poll query skips rows with delayed_until > now()

- `director-tools.test.ts` — two new tools:
  - `regen_scene_voice` with scene_id only → uses default voice from character/narrator
  - `regen_scene_voice` with voice_id override → passes override to fal
  - `regen_scene_voice` with text_override → uses override text
  - `regen_scene_voice` on scene without dialogue and no text_override → error
  - `compose_scene_final_clip` on scene without voice → error
  - `compose_scene_final_clip` happy path → final_clip job created

- `generateMasterClipAction.test.ts` — extend:
  - All scenes have final_clip → `has_full_audio: true`
  - One scene falls back to video → `has_full_audio: false`
  - All scenes are native with `has_native_audio` → `has_full_audio: true`

### 7.3 Manual E2E checklist (post-merge smoke on mangopro.ru)

1. **Russian happy path.** Create project, idea in Russian, generate script (3+ scenes with dialogue), characters, frames, videos. Wait ~1 min. Each scene player shows 🎵 badge. Click «Финализировать ролик» → master clip plays with voiced dialogue. Stage 05 badge shows 🎵.
2. **Mixed mode override.** Same as (1), but set scene 2 audio mode to `native`. Verify scene 2 player plays raw video (no TTS); other scenes still get TTS.
3. **English happy path.** Idea in English → all scenes go native path → no `voice` jobs in `media_jobs` table → master clip has Veo/Seedance audio. Badge 🎵.
4. **Retry on TTS failure.** Stub ElevenLabs to fail (env var override to invalid key). First voice job fails, second auto-retry fires after 15 s. If second also fails — red badge + manual retry button. Restore key → retry succeeds.
5. **Premature finalize → wait.** Click «Финализировать ролик» while some scenes still have voice/mux in flight. Dialog appears. Click «Дождаться (~2 мин)» → wait → master fires → 🎵 со звуком.
6. **Premature finalize → silent.** Same setup, click «Склеить без звука» → master fires immediately → 🔇 без звука badge in Stage 05.
7. **Director regen voice.** In chat: "Перегенерируй озвучку сцены 02 другим голосом" → Director calls `regen_scene_voice` → confirm card → approve → new voice version + auto-chained final_clip → player updates to new audio.

**Risk & mitigation:**

| Risk | Mitigation |
|------|-----------|
| Poll-loop enqueues voice jobs for already-completed chains (double charge) | `recordPendingJob` dedup on fingerprint; covered in existing test path |
| ElevenLabs cost spike from auto-chain | Cost meter visible in Stage 04 toolbar; cost hint on tile pre-discloses; 5-version cap on voice history prevents unbounded retries |
| Migration breaks Supabase Realtime subscriptions | Additive columns only; no RLS policy changes |
| Stage 05 player renders broken badge on legacy masters | `has_full_audio === undefined` branch returns null — no badge |
| Confirm dialog blocks user when retry-failed scenes pile up | "Склеить без звука" always available; per-scene deep links offer recovery |

## 9. Out of scope (deferred)

- `audio_mode: 'none'` (explicit silent mode) — current `native` covers it for Cyrillic; revisit if user requests pile up.
- Exponential backoff or circuit-breaker on provider health — single retry handles transients; deeper recovery deferred.
- Bulk Director tools (`regen_all_voices`, `voice_all_scenes`) — defer until usage warrants.
- `set_scene_audio_mode` Director tool — UI control already exists; chat is not the right surface for a per-scene toggle.
- Auto-regenerate master clip when any scene changes — wasteful; user-driven re-finalize is preferred.
