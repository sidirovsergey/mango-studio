# Phase 1.8.0a — Script schema adapter (reader-only)

**Date:** 2026-05-18 (split from 1.8.0 after Codex audit)
**Status:** spec v2 — Codex audit pass 1 closed (3 BLOCKER fixes applied: separate `image_prompt_text` channel for downstream models, scene-level `.passthrough()` + proper nullables, LLM-facing terminology frozen to legacy)
**Goal:** Make every script consumer in the codebase tolerate BOTH the existing v1.4 schema (`scene.description`, `scene.dialogue: single|null`, no `narrative_paragraph`, no `shots`) AND the future CJM schema (`scene.narrative_paragraph`, `scene.dialogue: Dialogue[]`, `scene.shots: ShotSpec[]`) through a single normalization layer — WITHOUT changing the generator schema, prompt, or storage format yet. This is a pure refactor that ships green and unlocks 1.8.0b (generator rewrite) to be done as a clean follow-up.

**Pre-requisite:** none — 1.8.0a is independent of v1.7.0/1.7.1 and can land first.

## 1. Motivation

Codex audit 2026-05-18 named this as the #3 blocker: «Stage 03 schema adapter before generator rewrite». Concrete consumer touchpoints found:

- `apps/web/src/components/workspace/stages/StageScript.tsx:337` — reads `script.scenes[].description` directly.
- `apps/web/src/components/workspace/stages/scenes/SceneSidePanel.tsx:227` — reads `scene.dialogue.text` (single, not array).
- `apps/web/src/server/actions/scripts.ts:331` — normalizes old scenes in-place.
- `packages/core/src/llm/schemas.ts:48` — Zod schema requires `description`, `description_ru`, `description_en`, `duration_sec`, single `dialogue` field.

If 1.8.0b (generator rewrite to `dialogue[] + shots[]`) lands without this adapter, every consumer above breaks. The «backward-compat reader» originally proposed inside 1.8.0 is large enough to deserve its own sub-phase + Codex pass, especially because the Director Agent's `regen_scene_description` tool, Stage 04 inline storyboard, and version history all consume the same shape.

By landing the adapter FIRST as a pure refactor, we get:
- Green test suite + green prod after merge with zero behavioral change.
- A single seam where 1.8.0b plugs in the new generator — no consumer changes needed.
- Codex audit can target schema correctness in 1.8.0a, then generator quality in 1.8.0b, separately.

## 3. Module: `@mango/core/llm/normalize-script.ts`

```typescript
import { z } from 'zod';

// Existing types (defined in schemas.ts / provider.ts) — re-imported
import type { Dialogue, ScriptOutput } from './provider';

export interface ShotSpec {
  shot_id: string;
  description: string;
  image_prompt: string;
}

export interface NormalizedScene {
  // Identity + timing (passthrough)
  scene_id: string;
  duration_sec: number;
  arc_role?: string | null;
  location?: string | null;

  // === Canonical for consumers — always present ===
  narrative_paragraph: string;
  dialogue: Dialogue[];
  shots: ShotSpec[];

  // === Legacy passthrough — for round-tripping back to generator/storage ===
  description: string;
  description_ru: string;
  description_en: string | null;
  legacy_dialogue: Dialogue | null;
}

export interface NormalizedScript {
  scenes: NormalizedScene[];
  characters: NormalizedScript['scenes'] extends Array<infer _S> ? unknown[] : never;
  // ... character normalization deferred to 1.8.0b if needed; current schema
  //     already exposes characters[] consistently.
  // Note: this spec keeps characters[] passthrough — only scenes change.
  raw: unknown;  // original input, for round-tripping in writers
}

export function normalizeScript(raw: unknown): NormalizedScript {
  // Zod accepts: existing schema OR future schema with optional new fields.
  // Codex blocker fix #2: scene-level .passthrough() so unknown scene fields
  // survive into parsed output; nullables explicitly .nullable() not .default('').
  const lenient = z.object({
    scenes: z.array(
      z.object({
        scene_id: z.string(),
        duration_sec: z.number(),
        arc_role: z.string().nullable().optional(),
        location: z.string().nullable().optional(),
        description: z.string().nullable().optional(),       // nullable, not default
        description_ru: z.string().nullable().optional(),
        description_en: z.string().nullable().optional(),
        dialogue: z.union([
          z.object({ speaker: z.string(), text: z.string() }).nullable(),
          z.array(z.object({ speaker: z.string(), text: z.string() })),
        ]).nullable().optional(),
        narrative_paragraph: z.string().nullable().optional(),
        shots: z.array(z.object({
          shot_id: z.string(),
          description: z.string(),
          image_prompt: z.string(),
        })).optional(),
      }).passthrough()    // ← preserve unknown scene-level fields
    ),
    characters: z.array(z.unknown()).default([]),
  }).passthrough();

  const parsed = lenient.parse(raw);

  const scenes: NormalizedScene[] = parsed.scenes.map((s) => {
    // Defensive coercion for nullable-or-missing fields.
    const description = s.description ?? '';
    const description_ru = s.description_ru ?? description;
    const description_en = s.description_en ?? null;

    // Codex blocker fix #1 + #3: two distinct canonical channels.
    //   narrative_paragraph — Russian, for UI rendering in StageScript/SceneSidePanel.
    //     Reason: UI is Russian-canonical, defaulting via description_ru.
    //   image_prompt_text — English-preferred, for downstream image/video models
    //     (Veo, Seedance, ffmpeg-api). Reason: model context quality requires English.
    //     Maintains v1.4 director-state-summary.ts:82 behavior (description_en ?? description).
    const narrative_paragraph = s.narrative_paragraph ?? description_ru;
    const image_prompt_text = description_en ?? description;

    // Normalize dialogue to array.
    let dialogue: Dialogue[];
    let legacy_dialogue: Dialogue | null = null;
    if (Array.isArray(s.dialogue)) {
      dialogue = s.dialogue;
      legacy_dialogue = s.dialogue[0] ?? null;
    } else if (s.dialogue) {
      dialogue = [s.dialogue];
      legacy_dialogue = s.dialogue;
    } else {
      dialogue = [];
      legacy_dialogue = null;
    }

    // Synthesize shots — one default shot per scene using image_prompt_text (English).
    const shots: ShotSpec[] = s.shots ?? [{
      shot_id: `${s.scene_id}_shot1`,
      description: image_prompt_text,
      image_prompt: image_prompt_text,
    }];

    return {
      scene_id: s.scene_id,
      duration_sec: s.duration_sec,
      arc_role: s.arc_role ?? null,
      location: s.location ?? null,
      narrative_paragraph,
      image_prompt_text,
      dialogue,
      shots,
      description,
      description_ru,
      description_en,
      legacy_dialogue,
    };
  });

  return {
    scenes,
    characters: (parsed.characters as unknown[]),
    raw,
  };
}
```

**Properties of `normalizeScript`:**
- **Idempotent** — `normalizeScript(normalizeScript(x).raw)` deep-equal `normalizeScript(x)`.
- **Round-trip via `.raw`** — returns the EXACT original input reference (no Zod-induced mutation), as long as writers persist the original input shape, not the normalized output.
- **Tolerant** — null/missing description fields coerce to empty string; `dialogue` accepts single, array, or null without throwing.
- **Pure** — no DB calls, no LLM calls, no side effects.

**Codex audit caveats applied (do NOT overstate):**
- `parsed.scenes` from Zod is NOT structurally identical to `raw.scenes` despite `.passthrough()` on each scene (Zod converts undefined→explicit-undefined-in-object on optional+nullable). Use `.raw` directly for round-trip persistence; use `parsed`/`scenes` only as read-canonical.
- Unknown TOP-level script fields survive (top-level `.passthrough()`).
- Unknown SCENE-level fields survive (scene-level `.passthrough()` per fix above).
- Character-level passthrough deferred — current consumers only need `id, name, description` from characters; treated as unknown[] for now.

## 4. Consumer refactor checklist

| Consumer | Current read | After 1.8.0a |
|---|---|---|
| `StageScript.tsx:337` | `script.scenes[i].description` | `normalized.scenes[i].narrative_paragraph` (Russian-canonical UI) |
| `SceneSidePanel.tsx:227` | `scene.dialogue?.text` | `scene.dialogue.map(d => d.text).join('\n')` (or list render) |
| `scripts.ts:331` (normalizer) | ad-hoc legacy migration | call `normalizeScript`; drop ad-hoc helper if redundant |
| `director-state-summary.ts:82` | `scene.description_en ?? scene.description` | **`scene.image_prompt_text`** (English-preferred — same default chain as before; do NOT switch to `narrative_paragraph` here) |
| Shot generation prompt builders (any image/video provider) | `scene.description_en` | **`scene.image_prompt_text`** |
| Director Agent `refine_scene_description` tool | reads `scene.description` | **Tool surface unchanged in 1.8.0a:** input param stays `description`, internal code reads from `scene.narrative_paragraph`. Writes back to `description_ru` + `description` (NOT `narrative_paragraph`). LLM never sees the new field name in tool schemas — prevents hallucination of «I updated narrative_paragraph» when the persisted field is description_ru. |
| `regenSceneTextAction` | regenerates `description` etc. | unchanged in 1.8.0a — generator still emits legacy; adapter synthesizes on read |
| Stage 04 inline storyboard | `scene.description` | `scene.narrative_paragraph` |
| Version history snapshots | stores raw `script` jsonb | unchanged (storage format frozen until 1.8.0b) |

**Writer policy in 1.8.0a:** all writers continue writing legacy fields (`description`, `description_ru`, `description_en`, `dialogue: single|null`). The adapter only normalizes on READ. This keeps `projects.script jsonb` stable.

**LLM tool surface freeze (Codex blocker #3 fix):** all Director Agent tool `inputSchema` and tool `description` strings keep legacy field names — `description`, not `narrative_paragraph`. New canonical names (`narrative_paragraph`, `image_prompt_text`) are internal-only in 1.8.0a. Plan task adds an explicit grep gate: `rg "narrative_paragraph" packages/core/src/llm/director-tools.ts` must return ZERO matches after the refactor. Field rename is the responsibility of 1.8.0b, alongside the actual generator change.

## 7. Risks

1. **Adapter drift** — adapter and future generator both define `narrative_paragraph` semantics; they must agree. Mitigation: 1.8.0b spec MUST cite this adapter; any new field added to generator goes through the adapter contract first.
2. **Director Agent tool surface** — `refine_scene_description` and similar tools currently take `description` as input parameter (visible in `inputSchema`). 1.8.0a keeps tool params as `description` (no surface change); internally the tool reads `narrative_paragraph` (== description_ru for legacy projects). Surface rename deferred to 1.8.0b.
3. **Snapshot test churn for asymmetric projects** — projects with `description !== description_ru` (English description, Russian description_ru) will show a one-time visible text shift after 1.8.0a (from English description to Russian description_ru). Verified zero such prod projects via SQL audit. Documented in `docs/audits/1.8.0a-stage-script-behavior-shift.md`. For symmetric projects (description == description_ru, the common case) — ZERO diff.
4. **Language flip for downstream model context** — Codex caught this: if `director-state-summary.ts` and shot prompt builders switched to `narrative_paragraph` (Russian-canonical), Veo/Seedance would receive Russian context where v1.4 sent English. Adapter ships TWO channels: `narrative_paragraph` (RU, UI) and `image_prompt_text` (EN, models). Each consumer picks the correct one explicitly. Regression test in `director-state-summary.test.ts` is the gate.
5. **Performance** — `normalizeScript` called on every Stage 03/04 render (~50/min during editing) + every Director Agent prompt build. Pure JS allocating ~8 scenes × small objects. Estimated <1ms per call on ≤8 scenes, but NOT zero. Plan task adds a `script`-identity-keyed memo at the Workspace boundary (`useNormalizedScript` hook with `useMemo`) before declaring done; bench under `vitest --reporter=verbose` if questioned.
6. **Zod parse cost on re-renders** — Zod validation is the heaviest part. Memoization above handles it. If hot-path issues emerge in prod, fall back to type-asserted pass-through with light defensive guards (no Zod) and rely on schema validation only at storage boundary.

## 8. Cross-cutting standards

- All TS code in `packages/core/src/llm/` (server-pure, no React).
- Idempotent + pure functions.
- Snapshot test fixtures in `packages/core/src/llm/fixtures/` with explicit "legacy / future" filenames.
- Codex audit at sub-phase boundary (this spec is one).
- No DB migration — pure code refactor.
