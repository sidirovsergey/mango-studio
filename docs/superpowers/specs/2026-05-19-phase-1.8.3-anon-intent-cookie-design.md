# Phase 1.8.3 — Anonymous → Authed Intent Preservation (Cookie-Based)

**Date:** 2026-05-19
**Author:** Claude (Opus 4.7)
**Status:** Draft (pre-Codex)

---

## 1. Problem

Public storyboard at `/p/[publicSlug]` shows a sticky-CTA `«Получить ролик»` / `«Открыть Pro-Студию»`. Anon users see the same CTA as authed ones — that's intentional (Phase 1.8.1 CJM).

Click path for anon:

1. Anon clicks CTA.
2. Client calls `requestRenderAction({projectId, publicSlug})`.
3. Server calls `createTopupAction({...intent...})`.
4. `createTopupAction` sees `user.is_anonymous === true` → `redirect('/login')`.
5. Intent payload (kind/project_id/return_to) **lost**.
6. After OTP verify → `router.push('/')` — anon lands on home, the «Получить ролик» journey is broken.

User must re-find the project, click CTA again, then completion works. Real-world: most drop here.

## 2. Goal

Preserve the intent across the auth detour so the post-login flow lands the user **directly on the ЮKassa confirmation URL** (or pending state) without touching the storyboard again.

## 3. Non-goals

- Not changing `createTopupAction` semantics (it stays the generic ledger entry).
- Not introducing OAuth or magic-link flows (1.6 OTP stays the auth primitive).
- Not building an "intent management UI" — single pending intent per browser, opaque.
- Not switching CTA UX (sticky stays as-is).
- Not changing `fn_get_or_create_intent` ownership semantics (already enforced — Phase 1.7.1).

## 4. Approach — HMAC-Signed httpOnly Cookie

A short-lived cookie carries the intent claim across the auth detour. `intent-actions.ts` writes it before redirecting anon to `/login`; `verifyOtpAction` reads + replays it on success.

### 4.1 Cookie shape

- Name: `mango_pending_intent`
- httpOnly + Secure + SameSite=Lax + Path=`/`
- TTL: 30 minutes (auth detour > 30 min → user starts fresh, acceptable)
- Value: `base64url(JSON(payload)) + "." + base64url(HMAC-SHA256(payload, secret))`
- Payload:
  ```ts
  type PendingIntentPayload = {
    kind: 'render' | 'studio';
    project_id: string;        // uuid
    return_to: string;          // /p/{slug} — same-origin path
    exp: number;                // unix ms, server-checked on read
  };
  ```

### 4.2 Secret

`PENDING_INTENT_SECRET` — 32+ byte env var (operator-supplied). Loaded once per server boot; no rotation infra in scope.

### 4.3 Why cookie (not URL bouncing, not server-side ledger)

| Option | Verdict |
|---|---|
| **Cookie (chosen)** | httpOnly = no JS exfil. Survives client navigation. Atomic single source. |
| URL `?next=/p/slug&intent=...` | Leaks via Referer to ЮKassa. Long URLs in clipboard / logs. |
| Server-side pending intent in DB | Need anon-id binding (no auth yet). Lifecycle complexity for ephemeral state. |

### 4.4 Defence-in-depth

Even if a cookie is stolen + replayed by user Y who didn't originate it:
- `fn_get_or_create_intent` enforces `projects.user_id = auth.uid()`. User Y doesn't own project X → `insufficient_privilege`. (Phase 1.7.1 closed this.)
- Cookie can't fabricate payment — `billing_payments` row is bound to current `auth.uid()` by createTopupAction.
- HMAC mismatch on tamper → reject silently.
- Expired → reject silently.

Cookie is **UX helper**, not a security gate.

## 5. Code changes (surface)

| File | Change |
|---|---|
| `apps/web/src/lib/auth/pending-intent-cookie.ts` | **NEW.** `setPendingIntent(payload)`, `consumePendingIntent()` (read+verify+clear), `peekPendingIntent()` (read-only, optional). |
| `apps/web/src/app/p/[publicSlug]/actions/intent-actions.ts` | `requestRenderAction` / `openProStudioAction`: before calling `createTopupAction`, check `supabase.auth.getUser().is_anonymous`. If anon → `setPendingIntent({kind, project_id, return_to})` + return `{ok: false, error: {code: 'auth_required', message: '...'}}` (caller redirects). |
| `apps/web/src/app/p/[publicSlug]/components/StickyCta.tsx` (client) | On `error.code === 'auth_required'`: `window.location.href = '/login'` (already redirects on action error, just need the code path). |
| `apps/web/src/app/login/actions/verifyOtpAction.ts` | On `ok: true`: `const pending = await consumePendingIntent()`. If present → `await createTopupAction({package_code, intent: pending})`. Return `{ok: true, user_id, next_url?: confirmation_url}`. |
| `apps/web/src/app/login/LoginForm.tsx` | On verifyOtp `ok` + `next_url` → `window.location.href = next_url` instead of `router.push('/')`. |
| `apps/web/.env.example` (or wherever env docs live) | Document `PENDING_INTENT_SECRET`. |

`createTopupAction` stays untouched — Phase 1.8.3 wires intent persistence *around* it, not *into* it.

## 6. Tests

| Layer | Test |
|---|---|
| Unit | `pending-intent-cookie`: encode→decode roundtrip; HMAC tamper → null; expired → null; malformed → null. |
| Unit | `pending-intent-cookie`: empty secret env → throw on encode (fail-loud, ops misconfig). |
| Integration | `requestRenderAction` anon → cookie header set; result `auth_required`. |
| Integration | `requestRenderAction` authed → cookie NOT set; passes through to `createTopupAction`. |
| Integration | `verifyOtpAction` with valid cookie + valid OTP → next_url present + cookie cleared. |
| Integration | `verifyOtpAction` with expired cookie + valid OTP → next_url absent; OTP success still returns. |
| Integration | `verifyOtpAction` with cookie referencing project user doesn't own (replay attack) → graceful fallback (next_url absent, log warn). |

## 7. Operator deploy steps

1. Generate secret: `openssl rand -base64 48`.
2. Add `PENDING_INTENT_SECRET` to Vercel prod env (Production + Preview scopes).
3. Redeploy.
4. Smoke: anon on /p/{slug} → CTA → /login → OTP → land on ЮKassa.

No DB migration needed. No new tables. No backfill.

## 8. Risk

- **Cookie size** — payload ~150 bytes encoded + HMAC ~88 bytes. Total cookie ~250 bytes. Below all browser limits.
- **Secret rotation** — out of scope; doc TODO for ops. Rotating invalidates all in-flight cookies (acceptable, max 30min impact window).
- **SameSite=Lax** — cookie sent on top-level cross-site GETs but not subresource POSTs. OTP verify is a same-origin Server Action POST → cookie attached. No issue.
- **ЮKassa redirect lifetime** — confirmation_url has its own TTL from ЮKassa (~1h typical). If user takes 30min on /login + another 30min before clicking pay, payment URL still valid. No new constraint.
- **Multi-tab race** — user opens CTA in tab A (cookie set), then CTA in tab B before logging in. Tab B's `setPendingIntent` overwrites tab A's. After login replay, only tab B's intent fires. Acceptable.

## 9. Out of scope (deferred)

- Multiple-pending-intent UI («continue your interrupted flow» on /profile).
- Intent persistence across browsers / devices (server-side anon-id binding).
- OAuth/social-login.
- Secret rotation tooling.
- Cookie deletion on explicit «отменить» / nav-away (cookie just TTL-expires).
