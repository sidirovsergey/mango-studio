# Phase 1.4 — Prompt Refactor (Director / Cinematography / Voice / Meta) — Design Spec

**Date:** 2026-05-12
**Status:** Spec complete, plan in `docs/superpowers/plans/2026-05-12-phase-1.4-prompt-refactor.md`
**Depends on:** `v1.3.5` (PR #8) merged to main + post-polish PRs #9–#18 applied to production
**Relates to:** `docs/phase-1.4-prompt-audit/00-summary.md` (77 findings, 13 critical) + 4 layer-specific findings docs (`01-` through `05-`)
**Audit deliverable:** `voices.md` (created 2026-05-12, sections per-voice with TBD axes pending verification)

## 1. Context & Motivation

Phase 1.3.5 + post-polish (PRs #9–#18) shipped a fully working storyboard pipeline. User reported in a live session 2026-05-12 that the **content quality** is poor: bad scripts, generic characters, inconsistent first frames, mediocre videos, drifting voices. Static audit ([`docs/phase-1.4-prompt-audit/`](../../phase-1.4-prompt-audit/)) found **77 prompt-engineering issues across 4 layers**, with **13 critical ones** that compound:

1. **Scene description is one unstructured Russian paragraph** — image/video models have no shot size, camera move, lighting recipe, or audio direction to work with; they invent each axis independently per scene, so scenes 1 / 2 / 3 don't look like the same cartoon. (F1, F2, F57)
2. **One video prompt sent to five engines** — Seedance Lite / Seedance 2.0 / Veo 3.1 / Kling 2.5 / LTX all receive the same string; no engine's grammar (Veo blocks, Seedance time-segments, Kling beat markers) is honoured. (F65)
3. **No audio direction line for Seedance 2.0** — engine generates random ambient sound that fights the TTS dub layer. (F66)
4. **Voice pool may not be what we think it is** — MCP returned anomalous payloads suggesting two distinct voice_ids (Antoni, Arnold) both alias to Adam in production. **Unverifiable from this machine — production API key required.** (F29)
5. **Director Agent has zero few-shot examples** — verbose Russian rules work today but every prompt edit is one regression away from Phase 1.2.5's hallucination class of bug. (F17, F81)
6. **No prompt-producing-prompt anywhere** — first-frame, video, voice prompts are string concatenation in code, can't adapt to engine / shot / theme variation. (F88)

Phase 1.4 = end-to-end prompt refactor across all 6 prompt surfaces in `packages/core/` + `apps/web/src/server/lib/`, with a new evaluation harness so future passes can re-validate without manual smoke testing.

## 2. Goals & Non-Goals

### Goals

- **Schema foundation:** add `visual_theme` block at script root (palette / lighting / lens / motion / mood). Add structured cinematography fields per scene (`composition`, `camera_movement`, `lighting`, `audio_direction`, `description_en`, `arc_role`). Add `tier` to script for tier-aware authoring. Idempotent additive jsonb — no SQL migration needed.
- **Script-author rewrite:** `SCRIPT_SYSTEM_PROMPT` becomes XML-structured, emits the new fields, generates English mirror description, enforces shot-cadence rule based on duration, enforces narrative arc.
- **Per-engine video prompt authors:** dispatch `buildVideoPrompt` on `model` id → engine-specific template (Seedance 2.0 Director Brief, Seedance Lite simplified Director Brief, Veo 3.1 block grammar, Kling 2.5 beat-marked timeline, LTX permissive generic). Each consumes the structured scene from script.
- **First-frame prompt rewrite:** engine-aware (nano-banana-2 vs pro), consumes structured composition + visual_theme + character refs, separate reference-cell flow (additive to dossier) for character ref so first-frame stops fighting the multi-panel layout.
- **Voice layer fixes:** per-character `voice_settings` (stability / similarity_boost / style / speed); narrator persona authored by Grok; `set_character_voice` Director tool with rendered-audio guard; voice-canary assertion in character diff/merge; drop dead `Character.voice.description` field.
- **Director Agent overhaul:** XML structure; 8 few-shot examples for hardest tool-routing cases; replace JSON-dump of script with structured summary; prompt caching on static prefix; extended thinking enabled; `refine_script` preserves Visual Theme.
- **Hygiene:** strip UI coupling from `CHAT_SYSTEM_PROMPT`, replace hardcoded cost numbers in tool descriptions with model-registry lookups, drop dead `composition_hint ?? ''` fallback.
- **Eval harness:** snapshot tests for every `build*Prompt` function, static rubric tests (7-axis cinematography coverage, audio-line presence, English-mirror presence), LLM-judge tests on a 5-scene canonical fixture set; round-trip generation tests as opt-in manual workflow.
- **Documentation:** sync `voices.md` after F29 verification (user supplies API key results); document the new prompt architecture; manual E2E checklist for the audit.

### Non-Goals (defer to Phase 1.5 / 1.6 or post-launch)

- **F31 (eleven_v3 route + audio tags)** — depends on fal.ai wrapping `eleven_v3`; until then we stay on `multilingual-v2`. Phase 1.5+.
- **F33 (voice-design author via `/text-to-voice/design`)** — custom voice per character. Phase 1.5+. Implies F31 first.
- **F88 (LLM-mediated prompt authoring with a dedicated Scene Prompt Author LLM call)** — Phase 1.4 does string-concatenation with engine-specific templates first (~80% of the gain, no extra LLM cost per scene). F88 can be added in Phase 1.5 if eval shows residual quality gap.
- **F29 voice-pool ID reconciliation** — user supplies verification result manually (curl with production API key); if IDs are wrong, replacing them is a 5-line follow-up commit. Phase 1.4 voice tooling is voice-id agnostic.
- **Round-trip generation in CI** — eval harness includes the test design and a runner script but does not gate CI on credit spend; manual / on-demand.
- **Custom voice cloning self-serve** — requires ElevenLabs subscription flow. Phase 1.6+.
- **Webhooks / cron reconcile** — Phase 1.4 production hardening was on the original Phase 1.4 wish-list (per Phase 1.3.5 spec); this scope-cut moves it to Phase 1.5.
- **Multi-segment dialogue in one scene** — 1 scene = 1 speaker stays.
- **English-language UI / TTS** — RU-first stays; English mirror is only for downstream image/video models.

## 4. Data Model Changes

### 4.1 Visual Theme (new, at script root)

```ts
export const VisualThemeSchema = z.object({
  palette: z.array(z.string()).min(3).max(6),  // hex strings, e.g. ['#F4E4BC', '#3D2914', '#E8B86D']
  lighting: z.string(),                         // recipe — "soft golden-hour key + warm fill + cool rim"
  lens: z.string(),                             // character — "85mm shallow DOF" / "24mm deep focus"
  motion: z.string(),                           // motion language — "locked-off + occasional slow dolly" / "handheld energy"
  mood: z.string(),                             // one-word — "cozy" / "tense" / "playful"
  film_look: z.string().optional(),             // optional grade — "Pixar 'Coco' saturated warm", "Studio Ghibli watercolour"
  avoid: z.array(z.string()).optional(),        // optional list of project-wide negative directives
});
export type VisualTheme = z.infer<typeof VisualThemeSchema>;
```

### 4.2 Scene cinematography fields (new, additive)

```ts
export const ShotSizeSchema = z.enum([
  'extreme_close_up', 'close_up', 'medium_close_up',
  'medium', 'full', 'wide', 'extreme_wide',
]);

export const CameraAngleSchema = z.enum([
  'eye_level', 'low_angle', 'high_angle', 'birds_eye', 'dutch', 'over_shoulder', 'pov',
]);

export const CompositionSchema = z.object({
  shot_size: ShotSizeSchema,
  angle: CameraAngleSchema,
  framing_notes: z.string().optional(),    // "subject left third, leading room right" / "negative space top half"
  subject_focus: z.string().optional(),    // character_id for primary subject in multi-char scenes
});

export const CameraMovementSchema = z.object({
  kind: z.enum([
    'static', 'dolly_in', 'dolly_out', 'pan_left', 'pan_right',
    'tilt_up', 'tilt_down', 'tracking', 'orbit', 'crane_up', 'crane_down',
    'whip_pan', 'handheld', 'pov_walk',
  ]),
  speed: z.enum(['slow', 'medium', 'fast']).default('medium'),
  lens_character: z.string().optional(),   // "shallow DOF" / "anamorphic flare" / "deep focus"
});

export const LightingSchema = z.object({
  recipe: z.string(),                       // "golden-hour rim + warm key" / "low-key chiaroscuro" / inherited from visual_theme.lighting
  time_of_day: z.string().optional(),       // "dawn" / "midday" / "dusk" / "night"
  key_direction: z.string().optional(),     // "back-right rim" / "overhead practical" / "frontal soft"
});

export const AudioDirectionSchema = z.object({
  ambient: z.string().optional(),           // "distant city hum, light traffic"
  music: z.string().optional(),             // "warm piano motif, slow tempo" / null when silent
  sfx: z.array(z.string()).optional(),      // ["footsteps at 2s", "door creak at 4s"]
  voice_notes: z.string().optional(),       // "whispered" / "stretched vowels on emphasis"
});

export const ArcRoleSchema = z.enum([
  'hook', 'setup', 'rising', 'climax', 'payoff', 'cta', 'beat',
]);
```

### 4.7 Migration

Node CLI `scripts/migrate-phase-1.4.ts`:

1. Iterates every project in env.
2. For each project, parses script with Phase-1.3.5 Zod schema (existing).
3. Maps to Phase-1.4 schema:
   - `description` → `description_ru` (verbatim copy); also stays in `description` for back-compat reader if any
   - `description_en: null` (Grok fills on next regen)
   - `composition: null`, `camera_movement: null`, `lighting: null`, `audio_direction: null`, `arc_role: null` (Grok fills on next regen)
   - `tier_at_gen: <inherited from project.config_overrides.tier or project.tier>`
   - `visual_theme: null` at script root (Grok fills on next regen)
   - `tier: <from project.config_overrides.tier or 'economy'>` at script root
   - `narrator_voice.persona: undefined` (left empty)
   - For each character: `voice.description` REMOVED if present; settings fields stay undefined; if `dossier.reference_image` missing, leave it (regen creates it)
4. Writes back to projects table.
5. Inverse script (`scripts/migrate-phase-1.4-inverse.ts`) restores Phase-1.3.5 shape — strips new fields, drops description_en, restores composition_hint as null.

```xml

  <current>{{current_scene}}</current>

</surrounding_scenes>

<task>
Return the FULL updated scene object (same schema). Change only what the instruction asks. Echo every other field verbatim from <current>.
</task>
```

### 5.5 `buildVideoPrompt` (per-engine dispatch)

New signature:

```ts
function buildVideoPrompt(input: VideoPromptInput): {
  prompt: string;
  image_refs: StoredAsset[];
  duration_sec: number;
  aspect_ratio: '9:16';
  negative_prompt?: string;  // for engines that accept a separate negative param
};
```

Dispatched on `input.model`:

- `bytedance/seedance-2.0/image-to-video` → Seedance 2.0 Director Brief (6-component, time-segmented if >5s, audio line mandatory, negative line)
- `fal-ai/bytedance/seedance/v1/lite/image-to-video` → Seedance Lite Director Brief (simpler, no native audio line, time-segmented at 10s)
- `fal-ai/veo3.1/image-to-video` → Veo 3.1 block grammar
- `fal-ai/kling-video/v2.5-turbo/standard|pro/image-to-video` → Kling beat-marked timeline
- `fal-ai/ltx-video` → permissive generic
- unknown model → generic with warning log

Each variant consumes the structured scene (`composition`, `camera_movement`, `lighting`, `audio_direction`, `description_en`) and emits the engine-specific format. Examples in plan task 1.4.C.

## 8. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Grok struggles with 2 large few-shot examples (longer prompt → quality regress on short briefs) | Eval rubric gates: snapshot + rubric tests run on every prompt change. If quality drops on 15s briefs, fall back to 1 example. |
| Sonnet 4.6 extended thinking adds latency (~3-5s per turn) | Make it opt-in via `EXTENDED_THINKING` env var. Default ON in production; can toggle off via env if latency complaints. |
| Migration script produces invalid output for an unexpected legacy shape | Idempotent + roundtrip test (forward then inverse must equal original). Run on staging dataset first. |
| F29 turns out true — Antoni & Arnold both alias Adam | Tooling work is voice-id agnostic. Once user supplies verification, follow-up commit replaces IDs in voices.ts; `voices.md` updated; existing characters with wrong IDs flagged for review by reading their last regenerated audio version. |
| Per-engine prompt templates diverge in quality vs Seedance 2.0 specifically | Eval LLM-judge has a per-engine score; if Kling or Veo regress, iterate that template only. |
| Prompt caching cost savings smaller than projected on Anthropic API | Acceptable — caching is not a regression, just less savings. |
| Reference image generation adds a fal call per character ($0.03-0.05) | Documented cost; visible in cost-meter. ~$0.20 per project added. Acceptable. |
| User-facing description stays `description_ru`; if user reads through Director Agent reply they see Russian. If model regen produces a description_ru that differs from description_en in meaning, audio (RU) and video (EN) drift. | Rubric test: `description_en` must be a faithful translation of `description_ru` — Sonnet judge with low budget. Manual review for the first batch of projects post-ship. |
