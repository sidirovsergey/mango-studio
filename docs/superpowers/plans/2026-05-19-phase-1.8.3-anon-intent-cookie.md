## Sub-phase A — Cookie helper

**File:** `apps/web/src/lib/auth/pending-intent-cookie.ts` (NEW)

### Tasks
- A1. Define `PendingIntentPayload` type + `PENDING_INTENT_COOKIE = 'mango_pending_intent'` + `TTL_MS = 30 * 60_000`.
- A2. `encodePendingIntent(payload, secret): string` — JSON.stringify, base64url, HMAC-SHA256 with `node:crypto.createHmac`. Return `payload_b64 + '.' + hmac_b64`.
- A3. `decodePendingIntent(token, secret): PendingIntentPayload | null` — split on `.`, verify HMAC with `timingSafeEqual`, parse JSON, check `exp > now`, validate shape (kind enum, project_id uuid regex, return_to starts with `/p/`). Any failure → null.
- A4. `setPendingIntent(payload: Omit<PendingIntentPayload, 'exp'>): Promise<void>` — read `process.env.PENDING_INTENT_SECRET` (throw if missing), encode, write cookie via `next/headers.cookies().set(...)`. Options: `httpOnly: true, secure: true, sameSite: 'lax', path: '/', maxAge: TTL_MS / 1000`.
- A5. `consumePendingIntent(): Promise<PendingIntentPayload | null>` — read cookie via `cookies().get(...)`, decode, delete cookie (`cookies().set({name, value: '', maxAge: 0})`). Returns null if absent / invalid / expired.

### Tests (`pending-intent-cookie.test.ts` — NEW)
- A-test-1. encode → decode roundtrip preserves payload.
- A-test-2. HMAC tampered (mutate one byte of HMAC suffix) → decode returns null.
- A-test-3. Payload tampered (mutate one byte of payload prefix) → decode returns null.
- A-test-4. Expired (`exp < now`) → decode returns null.
- A-test-5. Malformed (no `.`, empty, wrong base64) → decode returns null.
- A-test-6. `setPendingIntent` with missing `PENDING_INTENT_SECRET` env → throws "PENDING_INTENT_SECRET not set".

## Risk register

- **`createTopupAction` called from server-action context (verifyOtpAction) instead of normal client invocation** — Server Action calling Server Action works in Next 16 (same request scope, same cookies). Verified by 1.7.1 (webhook → fn_settle_paid_intent via service role; here we call within authed cookies fresh from `verifyOtp` set-cookie). However: `verifyOtp` itself just set the Supabase session cookie via `setAll` callback. The subsequent `createTopupAction` call in the same request needs to see that session. Validate in C-test-2 by asserting `auth.getUser()` returns the verified user, not anonymous.
- **Stale cookie after login** — If user later submits another intent without going through this flow, no stale state since `consumePendingIntent` deletes.
- **Cross-user cookie replay** — Already defended by `fn_get_or_create_intent` ownership gate (Phase 1.7.1). Just log + drop silently.
