## 5.4 Точка перехода API → собственная инфраструктура

Сравнение (100% utilization, самая экономичная связка):

| Категория | Лучшая цена API | Лучшая цена self-host (100% util.) | Self-host дешевле, если utilization ≥ |
|---|---:|---:|---:|
| Изображение (Flux schnell/dev) | $0.0006 (Runware) | $0.00062–0.0036 (SDXL/Flux на 4090/H100) | Self-host НЕ выгоден при текущих ценах Runware — API дешевле почти при любой utilization на этом сегменте |
| Видео (Wan-класс, 5с) | $0.05/сек = $0.25/видео (fal.ai Wan 2.5) | $0.071/видео (Wan2.1 480p, H100, 100% util.) | Self-host выгоден уже при **~30-40% utilization** (0.071/0.4≈0.18 против API $0.25) — see расчёт ниже |

**Расчёт точки перехода для видео (наиболее значимая категория по себестоимости):**
API-цена Wan-класса через fal.ai ≈ $0.05/сек × 5 сек = $0.25/видео.
Self-host H100 при 100% utilization = $0.071/видео → **в 3.5 раза дешевле API уже при полной загрузке**.
При utilization U: стоимость self-host = $0.071/U. Точка равенства с API: $0.071/U = $0.25 → U ≈ **28%**.
**Вывод [EST]:** для видео-генерации собственная GPU-инфраструктура становится выгоднее API уже при загрузке GPU от **~30%** — то есть при относительно скромном, но стабильном потоке видео-задач (грубая оценка: 1 H100 на 100% utilization даёт 42 видео/час × 24 ч ≈ 1000 видео/сутки; при 30% utilization — уже ~300 видео/сутки достаточно, чтобы окупить содержание GPU дешевле API).

Для изображений точка перехода **не наступает** при текущих ультра-низких ценах API-агрегаторов (Runware $0.0006/изображение) — держать собственный GPU под фото нерентабельно почти при любой загрузке до объёмов в сотни тысяч изображений/сутки на одну карту.

## 5.5 Рекомендация

- **Изображения — только через API** (Runware/DeepInfra/fal.ai), self-host не оправдан при текущей ценовой конкуренции агрегаторов.
- **Видео — гибридная стратегия**: на MVP и до устойчивых ~300+ видео/сутки (по одной модели) — через API (fal.ai Wan/Kling). После достижения этого объёма — рассмотреть self-host на арендованных H100 (RunPod/Vast.ai, НЕ покупка железа) для профильной модели с наибольшим объёмом трафика, с сохранением API как fallback/burst-capacity.
- **Не покупать GPU в собственность** на горизонте этого исследования — аренда (Vast.ai/RunPod/TensorDock) обеспечивает достаточную экономику без capex и рисков простоя оборудования.
